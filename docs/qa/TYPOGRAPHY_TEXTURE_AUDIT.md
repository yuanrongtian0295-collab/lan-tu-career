# 字体与贴图安全区审计（仅方案，尚未改动全局样式）

审计范围：390px iOS 网页主流程、首页、生涯、比赛、手机、球员、联盟、休赛期与退役页。当前轮次只记录问题与治理方案；未调整全局 `@font-face`、通用标题字体、数字贴图字体和已有贴图安全区。

## 问题清单

| 优先级 | 问题 | 当前表现 | 建议治理 |
| --- | --- | --- | --- |
| P0 | 正文字号低于手机可读下限 | 多处说明、日期、元信息只有 7–9px，贴图纹理和屏幕缩放后笔画粘连 | 正文不低于 12px；元信息不低于 11px；按钮主文案不低于 14px；行高至少 1.35 |
| P0 | 贴图没有独立安全区 | 文字使用固定 padding 叠在撕纸、笔刷边缘上，长中文会碰到透明或高噪声区域 | 为每张皮肤声明 `--safe-top/right/bottom/left`，组件只能在安全区内排版 |
| P0 | 背景被非等比拉伸 | 多处 `background-size: 100% 100%` 会随内容高度拉伸边框与安全区 | 面板改用九宫格切片或 `border-image`；装饰层和内容底色分离 |
| P1 | 稀疏中文字库与系统字体混排 | `unicode-range` 只覆盖部分标题字，单个标题内会出现字宽、基线和粗细跳变 | 自定义字体只用于完整覆盖的短标题；否则整句使用同一套系统黑体 |
| P1 | 数字贴图字体被全局继承 | `strong/b/time` 同时包含中文和数字时发生逐字回退，行盒高度不稳定 | 数字拆成独立 `.sticker-number`；中文标签保持系统字体，不在同一节点混排 |
| P1 | 全局噪点位于文字上层 | `body::before` 的高层级纹理会覆盖正文，细笔画对比度下降 | 噪点放到页面背景层；文字与交互层必须高于纹理层，正文下方保留实色衬底 |
| P1 | 绝对定位文案缺少长度策略 | 球员名、球队名、事件标题变长时容易顶到贴图边缘 | 组件提供两行上限、自动缩放档位、ellipsis 与长名称测试样例 |
| P2 | 透明纹理后的对比度不稳定 | 同一颜色文字在亮纸纹、暗涂鸦和图片上可读性不同 | 正文对比度目标 4.5:1；元信息至少 3:1；必要时使用局部半透明实色层而非文字阴影补救 |

## 推荐实施顺序

1. 建立字体角色：`display`、`title`、`body`、`meta`、`number-sticker`，禁止通配选择器分配贴图字体。
2. 建立贴图安全区清单，为每个 PNG/SVG 记录原始尺寸、可拉伸区和内容区。
3. 将高频面板迁移到九宫格：剧情选择、日历纸张、手机卡片、球员属性托盘、赛季结算条。
4. 统一移动字号和行高，并加入长球员名、长球队名、三位数、负号与中英文混排样例。
5. 建立 375/390/430px、DPR 2/3 的视觉回归截图；检查溢出、贴边、截断、对比度和基线。

## 本轮有意例外

手机“场边动态”已单独改成系统字体与纯色高对比信息流，这是页面级可读性修复，不改变全局字库与其他贴图组件。生涯新日历的翻页栏同样使用系统字体，避免新增混排问题。
